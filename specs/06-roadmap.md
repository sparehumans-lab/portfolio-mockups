# 06. 로드맵과 마일스톤

자체 프로젝트이므로 날짜 없이 순서와 완료 기준으로 관리합니다. 각 마일스톤은 완료 기준을 모두 통과해야 다음으로 넘어갑니다.

## 마일스톤
| # | 목표 | 완료 기준 |
|---|---|---|
| M0 | 계정·보안 준비 | 아래 계정 체크리스트 완료, 모든 계정에 패스키 2개 등록, 복구 코드 보관 |
| M1 | 인프라 가동 | 저장소 푸시, Supabase 스키마 적용(staging·production), 공개 주소 접속, keepalive·ci 통과, v0.1.0 배포 |
| M2 | 데모 A 완성 | A 스펙 수용 기준 전부 통과(DB 모드), v0.2.0 |
| M3 | 데모 C 완성 | C 스펙 수용 기준 통과(정원 경합 포함), v0.3.0 |
| M4 | 데모 F 완성 | F 스펙 수용 기준 통과, v0.4.0 |
| M5 | v1.0.0 릴리스 | 목차 정리, 모바일·접근성 점검, 전체 수용 기준 재확인 |
| M6 | 운영 | 월 1회 점검, 필요 시 B·D·E 데모 추가 |

순서 조정: M3·M4 는 서로 바꿀 수 있습니다. M0 와 M1 은 고정입니다.

## 위험과 대응
| 위험 | 대응 |
|---|---|
| 계정 생성·인증 지연 | M0 를 최우선, 지연 시 메모리 모드로 데모 개발 계속 |
| 무료 DB 일시 중지(1주 무활동) | keepalive 워크플로, 배포 점검 |
| Supabase 무료 활성 프로젝트 2개 제한 | staging·production 으로 모두 사용, 다른 용도 프로젝트는 만들지 않음 |
| 패스키 분실로 계정 잠김 | 패스키 2개 이상, 복구 코드 오프라인 보관 |

## 계정 체크리스트 (M0)
| 순서 | 서비스 | 용도 | 패스키 |
|---|---|---|---|
| 1 | 패스키 보관 수단(휴대폰 + PC 또는 보안 키) | 모든 패스키의 기반 | - |
| 2 | Google 계정(개인 Gmail, 전용 계정 권장) | 로그인 기반, 복구 수단 | 지원 |
| 3 | GitHub | 저장소, Actions, Pages, GHCR | 지원(공식 확인) |
| 4 | Supabase | DB·REST. 무료 플랜 활성 프로젝트 2개 | 대시보드는 GitHub 로그인 연동(GitHub 패스키가 보호) |
| 5 | Hostinger(선택) | 도메인·VPS | 지원 미확인 → Google 연동 + 2단계 인증 |
